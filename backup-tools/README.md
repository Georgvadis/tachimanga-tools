# Утилиты для TachiManga

Набор скриптов для работы с резервными копиями TachiManga (`.tmb`).

## Файлы проекта

- `import/` — папка для исходных `.tmb`-бэкапов
- `output/` — папка со сгенерированными файлами
- `extract.py` — извлечение ссылок из бэкапа по категориям
- `categorize.py` — раскладка манги по буквам A–Z
- `restore_library.py` — восстановление библиотеки и категорий после того, как облако перетёрло локальное состояние
- `CLAUDE.md` — внутренние заметки по структуре `.tmb` и логике облачного синка (читать перед операциями над синхронизацией)

## extract.py — Извлечение ссылок

Разбирает резервную копию, извлекает категории из библиотеки и сохраняет ссылки по категориям в текстовый файл. По умолчанию обрабатывает **все источники** без фильтрации по доменам.

### Что сохраняется в output

- `<backup>_all_sources_by_category.txt` — ссылки, сгруппированные по категориям
- `<backup>_all_sources_by_category.txt.skipped.tsv` — записи, которые не удалось экспортировать
- `<backup>_tachimanga.db` — извлечённая база данных

Если в файле `.skipped.tsv` есть только заголовок, значит пропусков нет.

### Запуск

Если в папке `import/` лежит единственный `.tmb`-файл, путь можно не указывать:

```bash
./extract.py
```

Либо указать файл явно:

```bash
./extract.py import/backup.tmb
```

### Просмотр доступных источников

```bash
./extract.py backup.tmb --list-sources
```

### Фильтрация

Оставить только конкретные источники:

```bash
./extract.py backup.tmb --source-name "E-Hentai" --source-name "Hitomi"
```

Исключить определённые источники:

```bash
./extract.py backup.tmb --exclude-source "Local source"
```

Ограничить по доменам:

```bash
./extract.py backup.tmb \
    --allowed-domain "e-hentai.org" --allowed-domain "exhentai.org"
```

### Указание другого пути

```bash
./extract.py backup.tmb --output custom/result.txt
```

Если `--output` указывает на существующую папку, скрипт создаст в ней файл со стандартным именем.

### Формат итогового txt

- имя резервной копии
- список выбранных источников и доменов
- статистика по источникам (сколько ссылок из каждого)
- общее количество категорий и ссылок
- блоки категорий вида `## НазваниеКатегории (число ссылок)`
- ссылки с названием манги: `https://...  # Название`

## categorize.py — Категоризация по буквам

Читает `.tmb`-бэкап, раскладывает мангу по категориям-буквам (A, B, …, Z, `#`) на основе первой буквы артиста и упаковывает результат в новый `.tmb`-файл, готовый для восстановления в TachiManga.

### Что делает

- Извлекает поле `artist` (или `author`) из базы данных
- Парсит заголовки вида `[Artist] ...`, `[Circle (Artist)] ...`, `(Event) [Circle (Artist)] ...`
- Для оставшихся — запрашивает теги `artist:` и `group:` через E-Hentai / ExHentai API (если есть `cookies.txt`)
- Берёт первого артиста (для `A, B` — `A`; для `Foo | Bar` — `Foo`) и определяет букву по его первой латинской букве
- Создаёт категории `A`, `B`, …, `Z` и `#` (для всего, что не попадает в латиницу) — только те, в которые есть что положить
- Удаляет мангу из всех старых категорий — каждая манга остаётся только в своей букве
- Удаляет старые пустые категории
- Мангу, у которой артист не определяется, помещает в категорию «Неизвестно» (после системных, перед буквами)
- Не трогает системные категории: Запланировано, Прочитано, Брошенно, Читаю, Отложено
- Сбрасывает синхронизацию (`enable=0`, очищает `SyncCommit`/`ChapterSync`, всё помечает `dirty=1`, `commit_id=0`) — после восстановления приложение будет считать всё новым

### Запуск

Предварительный просмотр (без изменений):

```bash
./categorize.py --dry-run
```

Полная категоризация:

```bash
./categorize.py
```

Результат сохраняется в `output/<backup>_by_artist.tmb`.

### E-Hentai API

Для манги без поля `artist`/`author` и без распознаваемого заголовка скрипт может запросить теги через API. Создайте файл `cookies.txt` в корне проекта:

```
igneous=ваш_igneous
ipb_member_id=ваш_id
ipb_pass_hash=ваш_hash
```

Куки подхватываются автоматически. Для отключения API: `--no-api`.

### Опции

```bash
# Только артисты с >= 3 мангами
./categorize.py --min-count 3

# Использовать поле author вместо artist
./categorize.py --field author

# Использовать оба поля
./categorize.py --field both

# Указать конкретный бэкап и путь выхода
./categorize.py import/backup.tmb -o output/result.tmb

# Указать другой файл с куками
./categorize.py --cookies path/to/cookies.txt

# Без обращения к E-Hentai API
./categorize.py --no-api

```

## restore_library.py — Восстановление после облачной перезаписи

Если облачная синхронизация Tachimanga перетёрла локальное состояние (манга стала `in_library=0`, привязки к категориям пропали, системные категории помечены удалёнными), используй этот скрипт чтобы вернуть библиотеку из "хорошего" бэкапа, **сохранив cloud commit_id** — push после восстановления пойдёт как обновление существующих записей, а не создание новых.

### Что делает

- Берёт из source-бэкапа список манг, которые должны быть в библиотеке, и их категории, включая системные
- В post-sync бэкапе для каждой такой манги:
  - `in_library=1`, `default_category=0`, `dirty=1`, обновляет `update_at`
  - Сохраняет `commit_id` от облака — push улетит как UPDATE
- Добавляет отсутствующие `CategoryManga` привязки к существующим категориям из source-бэкапа
- Помечает буквы `dirty=1`

Системные русские категории (Запланировано, Прочитано, Брошенно, Читаю, Отложено) скрипт восстанавливает из `is_delete=1` и возвращает привязки к ним из source-бэкапа.

### Запуск

```bash
./restore_library.py <post_sync>.tmb <good_source>.tmb [-o output.tmb]
```

Пример:

```bash
./restore_library.py import/Tachimanga_backup_after_sync.tmb output/Tachimanga_backup_by_artist.tmb
```

Результат: `output/<post_sync>_relib.tmb`.

## План действий: облако перетёрло категории/библиотеку

1. **Сделать резервную копию текущего состояния** в самом приложении и закинуть в `import/` — это `post_sync.tmb`.
2. **Найти "хороший" бэкап** с правильной библиотекой и категориями (например, последний `output/*_by_artist.tmb`).
3. **Запустить `./restore_library.py`** на этих двух бэкапах.
4. **Проверить системные категории** в полученном файле:
   ```sql
   SELECT name, is_delete FROM Category
   WHERE name IN ('Запланировано','Прочитано','Брошенно','Читаю','Отложено');
   ```
   Скрипт автоматически снимает `is_delete=1` у существующих системных категорий.
5. **Восстановить полученный `_relib.tmb`** в приложении.
6. Убедиться что залогинен в **тот же** аккаунт, что и до синка.
7. **Включить синхронизацию** в настройках приложения.
8. Запустить sync вручную → push должен донести `in_library=1` для манг (по правильным `commit_id`) и пересоздать привязки.

Подробности по структуре `.tmb` и поведению облачного синка — в `CLAUDE.md`.
