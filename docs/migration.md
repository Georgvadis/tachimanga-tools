# Объединение проектов

`extractor-db` и `nsfw-ext` объединены в `tachimanga-tools`. Оба исходных набора коммитов сохранены без переписывания: перемещения выполнены отдельными коммитами, затем истории объединены.

| Раньше | Теперь |
|---|---|
| `extractor-db/*.py` | `backup-tools/*.py` |
| `extractor-db/import/`, `output/`, `cookies.txt` | те же пути внутри `backup-tools/` |
| Gradle, `src/`, `scripts/` в `nsfw-ext` | внутри `extensions/` |
| `nsfw-ext/signingkey.jks` | `extensions/signingkey.jks` |

На основной машине локальные бэкапы, результаты, cookies, готовый `repo/` и прежний ключ подписи скопированы в новые папки. Оригинальные каталоги сохранены как резервные копии. Для дальнейшей разработки используйте `/srv/storage-1/projects/tachimanga-tools`.

После клонирования на другой машине перенесите эти данные вручную. Они исключены из Git. Не создавайте новый ключ подписи для существующих расширений.

## Публикация

Исходники и публикация расширений теперь находятся в одном публичном репозитории `Georgvadis/tachimanga-tools`. GitHub Pages использует ветку `gh-pages`, каталог `/`. Готовые APK перенесены без пересборки; ключ подписи и идентификаторы источников сохранены.

Новый адрес для TachiManga:

```text
https://georgvadis.github.io/tachimanga-tools/index.min.json
```

Резервный адрес без ожидания GitHub Pages:

```text
https://raw.githubusercontent.com/Georgvadis/tachimanga-tools/gh-pages/index.min.json
```

В настройках репозиториев расширений добавьте новый адрес, обновите список и убедитесь, что видны E-Hentai и Hitomi. Затем удалите старый адрес. Переустанавливать расширения из-за переноса не нужно. Библиотека и её источники не меняются.

После проверки на устройстве можно удалить оба старых GitHub-репозитория. Удаление `Nsfw-ext` отключит старый адрес; GitHub не перенаправит его на новый. Локальные исходные каталоги пока сохранены как резервные копии.

`build_repo.sh` по умолчанию задаёт `https://georgvadis.github.io/tachimanga-tools`. Адрес можно переопределить через `REPO_WEBSITE`.

`publish_pages.sh` использует самостоятельный clone существующей ветки `gh-pages`, по умолчанию в `.cache/tachimanga-pages` корня проекта. Он проверяет адрес remote, ветку и отсутствие незакоммиченных изменений, получает обновления без переписывания истории и копирует только готовое содержимое `extensions/repo/`.

Параметры: `PAGES_REPOSITORY_URL`, `PAGES_BRANCH`, `PUBLISH_DIR`, `PAGES_COMMIT_MESSAGE`. Ветка должна уже существовать. При публикации в другой репозиторий также задайте соответствующий `REPO_WEBSITE` при сборке.

Старые `.cache/extension-pages` и worktree `nsfw-ext-pages` больше не используются. Нельзя указывать исходники проекта в качестве `PUBLISH_DIR`. При ошибке публикации проверьте выделенный каталог: скрипт сохраняет изменения для разбора и повторного ручного push.

## Проверка миграции

Источники подхода:

- [Git merge: объединение независимых историй](https://git-scm.com/docs/git-merge)
- [GitHub Pages API: создание сайта и проверка сборки](https://docs.github.com/en/rest/pages/pages)
- [GitHub Pages: источник публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
- локальные исходники, README, скрипты релиза и инструкции обоих проектов.

Сборка APK требует Java и Android SDK. Восстановление бэкапа непосредственно в TachiManga и облачная синхронизация проверяются отдельно в приложении.

Фактическое имя репозитория размещения — `Nsfw-ext`. GitHub API и Git remote принимают другое написание регистра, но путь Pages чувствителен к регистру: прежние инструкции с `/nsfw-ext/` возвращали 404. Старый рабочий адрес — `/Nsfw-ext/`; новая публикация использует `/tachimanga-tools/`.

## Результаты проверки на основной машине

- Git 2.53.0, Python 3.14.4, Gradle wrapper 8.14.3; версии зависимостей расширений сохранены.
- На реальном `.tmb` сравнили старые и новые версии всех трёх утилит: экспорт совпал побайтово, данные SQLite совпали без временных меток изменения.
- Для новых `.tmb` проверили SHA-1, размер содержимого и сохранность всех дополнительных файлов архива.
- Отсутствующий бэкап корректно отклоняется.
- Шесть локальных проверок реального Git-процесса публикации проходят, включая повторный запуск и ошибочные состояния.
- Компиляция Python, синтаксис shell и `git diff --check` проходят.
- Реальный запуск публикации с существующими артефактами сообщил отсутствие изменений; содержимое рабочего Pages index совпало с локальным, GitHub Pages имеет статус `built`.
- Полную сборку APK не запускали: на машине отсутствуют Java и Android SDK. Восстановление в самом приложении и облачную синхронизацию не проверяли; перенос не изменяет логику обработки бэкапов.

## Проверка переноса публикации

- Публикация перенесена в `tachimanga-tools/gh-pages`, настройки Pages: ветка `gh-pages`, каталог `/`.
- GitHub Pages сообщил `built`; новый `index.min.json` вернул HTTP 200.
- `index.min.json`, `index.json` и `repo.json` получены по новому Pages-адресу и совпали с локальными артефактами.
- Оба APK скачаны через Pages и raw-адрес, их SHA-256 и байты совпали с исходными APK. Отпечаток ключа подписи сохранён.
- Шесть тестов публикации проходят. Повторная реальная публикация корректно сообщает отсутствие изменений.
- APK не пересобирались. Добавление нового адреса и обновление списка в самой TachiManga остаётся проверить на устройстве пользователя.
