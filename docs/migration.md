# Объединение проектов

`extractor-db` и `nsfw-ext` объединены в `tachimanga-tools`. Оба исходных набора коммитов сохранены без переписывания: перемещения выполнены отдельными коммитами, затем истории объединены.

| Раньше | Теперь |
|---|---|
| `extractor-db/*.py` | `backup-tools/*.py` |
| `extractor-db/import/`, `output/`, `cookies.txt` | те же пути внутри `backup-tools/` |
| Gradle, `src/`, `scripts/` в `nsfw-ext` | внутри `extensions/` |
| `nsfw-ext/signingkey.jks` | `extensions/signingkey.jks` |

На основной машине локальные бэкапы, результаты, cookies, готовый `repo/` и прежний ключ подписи скопированы в новые папки. Оригинальные каталоги сохранены как резервные копии. Для дальнейшей разработки используйте `/srv/storage-1/projects/tachimanga-tools`.

После клонирования на другой машине перенесите эти данные вручную. Они исключены из Git. Не создавайте новый ключ подписи для существующих расширений.

## Публикация

Репозиторий исходников публичный. В `nsfw-ext` остаётся размещение готовых расширений по прежнему адресу; `main` старых репозиториев — исторические копии, актуальный код находится в `tachimanga-tools/main`.

`build_repo.sh` по умолчанию задаёт прежний адрес `https://georgvadis.github.io/Nsfw-ext`, независимо от `origin` нового проекта. Его можно переопределить через `REPO_WEBSITE`.

`publish_pages.sh` использует самостоятельный clone существующей ветки `gh-pages`, по умолчанию в `.cache/extension-pages` корня проекта. Он проверяет адрес remote, ветку и отсутствие незакоммиченных изменений, получает обновления без переписывания истории и копирует только готовое содержимое `extensions/repo/`.

Параметры: `PAGES_REPOSITORY_URL`, `PAGES_BRANCH`, `PUBLISH_DIR`, `PAGES_COMMIT_MESSAGE`. Ветка должна уже существовать. При публикации в другой репозиторий также задайте соответствующий `REPO_WEBSITE` при сборке.

Старый worktree `nsfw-ext-pages` не используется новым скриптом. Нельзя указывать исходники проекта в качестве `PUBLISH_DIR`. При ошибке публикации проверьте выделенный каталог: скрипт сохраняет изменения для разбора и повторного ручного push.

## Проверка миграции

Источники подхода:

- [Git merge: объединение независимых историй](https://git-scm.com/docs/git-merge)
- [GitHub Pages: источник публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
- локальные исходники, README, скрипты релиза и инструкции обоих проектов.

Сборка APK требует Java и Android SDK. Восстановление бэкапа непосредственно в TachiManga и облачная синхронизация проверяются отдельно в приложении.

Фактическое имя репозитория размещения — `Nsfw-ext`. GitHub API и Git remote принимают другое написание регистра, но путь Pages чувствителен к регистру: прежние инструкции с `/nsfw-ext/` возвращали 404. Рабочий адрес — `/Nsfw-ext/`.

## Результаты проверки на основной машине

- Git 2.53.0, Python 3.14.4, Gradle wrapper 8.14.3; версии зависимостей расширений сохранены.
- На реальном `.tmb` сравнили старые и новые версии всех трёх утилит: экспорт совпал побайтово, данные SQLite совпали без временных меток изменения.
- Для новых `.tmb` проверили SHA-1, размер содержимого и сохранность всех дополнительных файлов архива.
- Отсутствующий бэкап корректно отклоняется.
- Шесть локальных проверок реального Git-процесса публикации проходят, включая повторный запуск и ошибочные состояния.
- Компиляция Python, синтаксис shell и `git diff --check` проходят.
- Реальный запуск публикации с существующими артефактами сообщил отсутствие изменений; содержимое рабочего Pages index совпало с локальным, GitHub Pages имеет статус `built`.
- Полную сборку APK не запускали: на машине отсутствуют Java и Android SDK. Восстановление в самом приложении и облачную синхронизацию не проверяли; перенос не изменяет логику обработки бэкапов.
